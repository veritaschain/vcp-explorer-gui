# Certificate print/PDF accessibility: verified scope and limitations

**As of:** 2026-10-26  
**Applies to:** first-party VCP Explorer GUI mock certificate, not VCP/VAP conformance certification  
**Status:** `NATIVE_BROWSER_PRINT_ACCESSIBILITY_NOT_ESTABLISHED`

## User-facing behavior

The certificate page's **Print / Save as PDF** button calls the browser's
`window.print()`. Browsers and operating-system print dialogs decide what gets
saved. This application does not supply a custom tagged-PDF export or make
the browser print output a validated accessible PDF. Its on-screen certificate
and blockchain information are **demo data, not verified**, and the displayed
"certificate" is **not** a VeritasChain Certified (VC-Certified) result or a
compliance finding.

A PDF that looks correct and preserves complete IDs/hashes is not automatically
accessible to a screen reader. In particular, visual reading order and logical
tag reading order are different properties.

## Remaining acceptance criteria

The following are separately required before any claim of an accessible
export or PDF/UA conformance:

1. Specify a **real user-accessible export mechanism** and its generator, not
   merely a CI-only Chromium option. Keep this distinct from `window.print()`.
2. Review the document's semantic headings, language, alternative text for
   meaningful graphics, form/link navigation and reading order through an
   accessibility API or assistive technology. The observed `/NonStruct` roles
   are an inventory, not automatic failures or passes.
3. Exercise keyboard order, reading order and screen-reader output, including
   the two-column event/timestamp summary, Merkle proof, full identifiers and
   conspicuous **Demo data, not verified** caveat.
4. Use a suitable PDF accessibility validator and actual users/assistive
   technology for the intended target standard before asserting PDF/UA. A
   `StructTreeRoot` alone is not sufficient.
5. Preserve the existing no-certification/non-compliance language in every
   route, print output, report and candidate export. Keep real anchored
   evidence verification and certification status separate from styling.

Existing HTML automatic axe-core CI is helpful but does not substitute
for any PDF checks. Track further work in
[GUI Issue #6](https://github.com/veritaschain/vcp-explorer-gui/issues/6).
